### Что вообще от тебя требуется, глобально

Задача: сделать **мобильное приложение-мессенджер для Android** — как маленький Telegram, но свой. Пользователь регистрируется по email+паролю, видит список чатов, переписывается, отправляет картинки. Это учебный проект («Технонаставники»), у тебя 6 занятий по часу, роли: наставник (тимлид) + школьник (разработчик). В конце — защита на 7 минут.

**Всё бесплатное.** Платить за программы не надо, нужен только компьютер (от 8 ГБ памяти) и интернет.

### Программы, которые надо скачать (3 штуки)

1. **Android Studio** — главная программа. Это «мастерская», где пишут код и собирают приложение. Скачивается с сайта **developer.android.com/studio**. Большая (~1 ГБ), ставится долго. Внутри себя сразу содержит всё нужное (язык Kotlin, эмулятор телефона), ничего доустанавливать не надо.

2. **GitHub Desktop** — программа для отправки твоего кода на сайт GitHub. Скачивается с **desktop.github.com**. Простая, с кнопками.

3. **Эмулятор телефона** — виртуальный телефон внутри компьютера. Ставится через сам Android Studio (это не отдельный скачиваемый файл). Альтернатива — реальный телефон с Android 6.0 или выше, куда ставится готовый файл приложения.

### Где регистрироваться (3 аккаунта)

1. **Google-аккаунт** (обычная почта @gmail.com) — на **accounts.google.com**. Нужен для двух вещей: вход в Firebase и вообще всё от Google. Если у тебя уже есть Gmail — этот пункт закрыт.

2. **Firebase** — сайт **console.firebase.google.com**. Это «облачный сервер» от Google, который делает всю тяжёлую работу: хранит пользователей, сообщения, файлы. Регистрируешься туда своим Google-аккаунтом → создаёшь «проект» → включаешь три службы (ниже). Бесплатно.

3. **GitHub** — сайт **github.com**. Это «хранилище твоего кода» в интернете. Регистрируешь почту/пароль → создаёшь «репозиторий» (папку для кода) → через GitHub Desktop закидываешь туда свой код. Это обязательный пункт: без репозитория на GitHub проект не засчитают.

### Технологии — что это и зачем (простыми словами)

| Технология | Что это по-человечески | Где берётся |
|---|---|---|

### Какой код и что писать (по экранам)

Приложение состоит из 4 экранов, и код пишется именно под них:

1. **Экран регистрации** — поля «email», «пароль», кнопка «Зарегистрироваться». Код отправляет данные в Firebase Authentication.
2. **Экран входа** — те же поля, но с проверкой «есть ли такой пользователь».
3. **Экран списка чатов** — список людей/диалогов, с которыми переписываешься. Данные берутся из Firebase Realtime Database.
4. **Экран переписки (диалог)** — сообщения слева/справа, поле ввода, кнопка «отправить», кнопка «прикрепить картинку». Новые сообщения приходят **в реальном времени** (Firebase сам шлёт обновления). Картинки грузятся в Firebase Storage.

Плюс под капотом: **Room** сохраняет историю сообщений локально, чтобы после закрытия приложения ничего не пропало.

## Ответ 2 — Ассистент

### 1. Android Studio vs Godot

**Что это по сути:** Android Studio — это IntelliJ IDEA (ты пробовал) + встроенный «конструктор под Android». Фактически это IntelliJ, раздутая Google'ом под мобильную разработку. Официальная, бесплатная.

**Сравнение с Godot:**

| | Godot | Android Studio |
|---|---|---|
| Заточен под | Игры (сцены, ноды, экспорт) | Любые Android-приложения |
| Язык | GDScript/C# | Kotlin/Java |
| UI | Сцены + Control-ноды в редакторе | Код (Jetpack Compose) или XML-разметка |
| Экспорт APK | Кнопка «Export» из редактора | Сборка через Gradle |
| Тяжесть | ~100 МБ | ~1.2 ГБ установщик, **10–15 ГБ на диске** после SDK + эмулятор |
| Серверная часть | Нет из коробки | Firebase подключается из редактора |

**Платно/бесплатно:** Бесплатно полностью. SDK, эмулятор, всё — free. Платное ПО не требуется (прямым текстом в PDF).

**Подводные камни (по сравнению с Годотом):**

1. **Первый запуск качает «всё и сразу»** — после установки Android Studio при первом открытии скачивает Android SDK, Build-Tools, Platform-tools. Это ещё ~3-5 ГБ. Нужен стабильный интернет.
2. **Gradle** — система сборки. При создании первого проекта и при каждом «Sync» он качает зависимости из интернета. Первый запуск нового проекта может идти 5-15 минут. Это нормально, не паниковать. Сайт с зависимостями: `maven.google.com` и `repo.maven.apache.org` — доступны из РФ.
3. **Эмулятор требует виртуализацию** (VT-x у Intel / AMD-V у AMD) — включается в BIOS. Если не включена — эмулятор не стартует. **Обход:** тестировать на реальном телефоне (Android 6.0+) через USB-отладку — это проще и нагляднее. Для защиты проекта на телефоне даже лучше.
4. **JDK отдельно ставить не надо** — внутри Android Studio свой (JBR). В отличие от серверной Java-разработки, тут не надо возиться с JAVA_HOME.
5. **ОЗУ:** 8 ГБ — минимум, реально комфортно от 12-16. При 8 ГБ эмулятор + студия одновременно будут тормозить.
6. **Hyper-V / антивирусы** — если на ПК включён Hyper-V (например, от Docker или WSL), старый эмулятор может конфликтовать. Снова обход — реальный телефон.

### 2. Kotlin — что это технически

Язык от **JetBrains** (та компания, что сделала IntelliJ IDEA). Google сделал его основным языком для Android (Java — deprecated, но ещё работает).

- **Компилируется** в байт-код JVM → работает на Dalvik/ART Android.
- По стилю ближе к **TypeScript / C# / Java**: статическая типизация, null-safety (`String?` вместо null-тредов), data-классы одной строкой, функции первого класса, extension-функции.
- Если ты видел GDScript — там динамическая типизация, тут статическая. Компилятор будет ругаться на ошибки **до** запуска — это плюс, а не минус.
- Синтаксис простой: `val` = константа, `var` = переменная, `fun` = функция, `class` = класс.

```kotlin
fun main() {
    val name = "Игорь"        // val — неизменяемая
    var count = 0             // var — изменяемая
    count++
    println("$name, сообщений: $count")
}
```

### 3. Jetpack Compose

**Это библиотека для UI, не отдельная программа.** Подключается одной строкой в Gradle-файле проекта.

**Принцип — декларативный:** ты описываешь **каким должен быть экран** в данный момент, а не «создай кнопку, повесь обработчик, добавь в контейнер». Как в React/Flutter/Vue — если сталкивался.

Было (старый способ, XML-разметка + findViewById):
```xml
<Button android:id="@+id/btn" android:text="Войти" />
```
+ отдельный Kotlin-код, который находит эту кнопку.

Стало (Compose):
```kotlin
Button(onClick = { login() }) {
    Text("Войти")
}
```

Всё — и разметка, и логика — в одном месте, на Kotlin. Состояние (state) меняется → UI перерисовывается сам.

**Сравнение:** ближе всего к Godot-нодам, только без визуального редактора — всё кодом. Или как Flutter-виджеты, только привязанные к Android.

**Настраивать отдельно не надо** — в Android Studio при создании проекта выбираешь шаблон «Empty Activity (Compose)» — и всё подключено.

### 4. Firebase — что это и как настраивается

**Firebase = Backend-as-a-Service (BaaS)** от Google. Ты **не пишешь свой сервер**. Вместо этого Google даёт готовые службы, к которым приложение стучится через SDK.

**Сайт: console.firebase.google.com** (вход — обычный Google-аккаунт).

**Бесплатно.** Тариф Spark (free tier): аутентификация — без ограничений, Realtime Database — 1 ГБ хранилища / 10 ГБ/мес трафика, Storage — 5 ГБ. Для учебного мессенджера — с запасом.

#### Firebase Authentication
- Сервис аутентификации. Регистрация email+пароль, вход, выход.
- Хранит хэши паролей, выдаёт **ID-токен** (JWT) — приложение дальше работает с этим токеном.
- Подключается: в консоли включаешь провайдер «Email/Password» → в коде вызываешь `FirebaseAuth.createUserWithEmailAndPassword(email, password)`.
- Настраивается **без единой строчки серверного кода** — только галочка в консоли + вызовы в Kotlin.

#### Firebase Realtime Database
- NoSQL-база в облаке. Фактически — одно большое **JSON-дерево**.
- Главная фича: **слушатели** (`addListenerForSingleValueEvent` / `addValueEventListener`). Ты подписываешься на ветку `/chats/user123` → данные приходят **сами**, когда кто-то пишет. Отсюда «в реальном времени».
- Схема примерно так:
```json
{
  "chats": {
    "chat1": {
      "members": ["user1", "user2"],
      "messages": {
        "msg1": { "text": "привет", "from": "user1", "time": 1718000000 }
      }
    }
  }
}
```
- **Подводный камень №1:** у базы есть **права доступа (Rules)**. По умолчанию — `auth != null` или даже `false`. Без настройки прав приложение получит `Permission denied`. Права правятся прямо в консоли Firebase, вкладка «Rules».
- **Подводный камень №2:** это **не SQL**. Нет таблиц и JOIN — вложенные объекты, всё держится в памяти, синхронизируется целиком (для маленького мессенджера — ок).

#### Firebase Storage
- Хранилище файлов (картинки с галереи/камеры).
- Загрузка: `FirebaseStorage.getInstance().reference.child("images/$id").putFile(uri)` → потом берёшь download URL.
- Права доступа — отдельно, в правилах Storage (тоже в консоли).

#### Как всё это подключается к проекту (самое важное)

Это **единственная нетривиальная настройка**:

1. В консоли Firebase → «Add project» → создаёшь.
2. «Add app» → выбираешь **Android** → вводишь **package name** (например `com.example.messenger`) — это берётся из `build.gradle` твоего проекта.
3. Firebase даёт скачать файл **`google-services.json`** → ты кладёшь его в папку `app/` проекта Android Studio.
4. В `build.gradle` (project) добавляешь плагин: `classpath 'com.google.gms:google-services:4.4.x'`, в `build.gradle` (app) — `apply plugin: 'com.google.gms.google-services'` + зависимости Firebase (Auth, Database, Storage). Android Studio показывает готовые фрагменты — копируешь.
5. Жмёшь **«Sync Now»** → Gradle качает зависимости → всё подключено.

После этого в Kotlin-коде просто пишешь `FirebaseAuth.getInstance()` — и работаешь.

### 5. Room

**Room = обёртка над SQLite** (SQLite — встроенная в каждый Android-телефон база данных). Из «Jetpack» — официальных библиотек Google для Android.

**Зачем в мессенджере:** Firebase — облачная база (нужен интернет). Room — **локальная** база на самом телефоне. Сообщения копятся в Room → закрыл приложение, открыл без интернета → история на месте. Это как раз пункт из требований: «Локальное сохранение сообщений для офлайн-доступа» (5 баллов из 45).

**Как устроено** — 3 слоя:

```kotlin
@Entity                        // 1. Таблица (как строка в SQL)
data class Message(
    @PrimaryKey val id: String,
    val text: String,
    val chatId: String
)

@Dao                           // 2. Интерфейс запросов (CRUD)
interface MessageDao {
    @Insert fun insert(msg: Message)
    @Query("SELECT * FROM messages WHERE chatId = :id") fun getForChat(id: String): List<Message>
}

@Database(entities = [Message::class], version = 1)  // 3. Сама БД
abstract class AppDatabase : RoomDatabase() { ... }
```

**Сравнение:** если ты работал с SQL-базами — это ORM поверх SQLite (как Hibernate/JPA в Java-мире). Если нет — представь structured JSON, который лежит в одном файле телефона и к которому есть типизированные запросы.

**Подключение:** одна зависимость в Gradle (`androidx.room:room-runtime`) + `kapt`/`ksp`-плагин для аннотаций. Никаких внешних серверов, никакой регистрации — это 100% локально.

### 6. План действий — пошагово

#### Фаза 0. Подготовка ПК (один раз)
1. Проверить: ОЗУ ≥ 8 ГБ, свободно на диске **≥ 20 ГБ**, интернет.
2. Для эмулятора (опционально): проверить виртуализацию. В PowerShell: `systeminfo` → «Гипервизор: Да» = включена. Если нет — BIOS → VT-x/AMD-V. **Либо просто пропустить эмулятор и юзать реальный телефон** (проще).
3. Завести **Google-аккаунт** (если нет) — accounts.google.com.

#### Фаза 1. Android Studio (день 1, ~1-2 часа)
4. Скачать: **developer.android.com/studio** → установщик ~1.2 ГБ.
5. Запустить → Standard-тип установки → дождаться скачивания SDK (~10-15 мин, зависит от интернета).
6. Готово. Отдельно JDK/SDK/командные утилиты **не ставить**.

#### Фаза 2. Первый проект — «Hello World» (день 1)
7. Android Studio → **New Project → Empty Activity (Compose)** → имя проекта, package name (записать! он понадобится для Firebase), минимум SDK — **API 23 (Android 6.0)** — как в требованиях PDF.
8. Нажать зелёную кнопку **Run ▶** → выберётся эмулятор или телефон → увидишь пустое приложение. **Это критическая проверка:** если запустилось — среда настроена.
9. Для реального телефона: на телефоне «Для разработчиков» → «Отладка по USB» → подключить кабелем → телефон появится в списке устройств Android Studio.

#### Фаза 3. Firebase (день 1-2, ~30-60 мин)
10. **console.firebase.google.com** → «Create project» → название (например «Созвездие-мессенджер») → Google Analytics — можно выключить.
11. В проекте Firebase → иконка Android → ввести **package name** из шага 7 → скачать **`google-services.json`**.
12. Положить `google-services.json` в `app/` проекта в Android Studio (просто перетащить).
13. Следовать **интеграционному чеклисту Firebase** (он появится в консоли): добавить плагин + 3 зависимости в `build.gradle` → **Sync Now**.
14. В консоли Firebase включить:
    - **Authentication** → Sign-in method → **Email/Password → Enable**
    - **Realtime Database** → Create database → (регион) → **Rules** — на время разработки открыть тестовый режим, потом закрыть
    - **Storage** → Get started → Rules — аналогично
15. Проверка: запустить приложение, в `onCreate` написать `FirebaseAuth.getInstance()` — если не вылетает с `DefaultFirebaseApp` — подключилось.

#### Фаза 4. GitHub (30 мин, один раз)
16. **github.com** → регистрация.
17. **desktop.github.com** → установить → войти → File → Add Local Repository (папку проекта).
18. Важно: в корне проекта должен быть `.gitignore` (шаблон Android Studio создаёт его сам) — чтобы `build/` и `local.properties` не улетали в репозиторий.

#### Фаза 5. Непосредственно разработка (занятия 1-5 по PDF)
19. Занятие 1: экран регистрации/входа на Jetpack Compose (без Firebase, просто UI + навигация).
20. Занятие 2: подключить Firebase Auth → реальная регистрация/вход.
21. Занятие 3-4: модели данных, Realtime Database (список чатов + диалог + сообщения в реальном времени), Room для локальной истории, отметка «прочитано».
22. Занятие 5: отправка картинок (Firebase Storage), сборка **APK**: menu **Build → Build Bundle(s)/APK(s) → Build APK** → готовый файл лежит в `app/build/outputs/apk/debug/app-debug.apk`.

#### Фаза 6. Сдача (занятие 6)
23. **README.md** в репозитории: как собрать, как запустить, стек, структура.
24. Видео-демонстрация (7 мин защиты): регистрация → чат → сообщение в реальном времени → картинка.
25. Финальный `commit + push` на GitHub.
26. Презентация по 7-раздельной структуре из PDF.

### Главные отличия от Godot, если коротко

- **Нет единого редактора с кнопкой Export** — есть IDE + система сборки Gradle, которая живёт своей жизнью и первый раз качает долго.
- **Нет встроенного сервера** — вместо этого Firebase (в Годоте под multiplayer обычно сам сервер пишешь).
- **UI — код, не визуальные ноды** (хотя в Годоте ты наверняка это ценил).
- **Дебаг другое:** Logcat (поток логов) вместо вывода в консоль, вместо Play — Run-кнопка IDE.
