# Запуск проекта на другом компьютере

Инструкция для того, кто впервые открывает проект. Все шаги выполняются один раз,
кроме пункта 5 (запуск).

## 1. Что нужно установить

| Программа | Зачем | Где взять |
| --- | --- | --- |
| Android Studio | среда разработки, эмулятор, SDK | developer.android.com/studio |
| Android SDK 35 | компиляция проекта | ставится из Android Studio |
| JDK 17 | сборка Gradle | входит в Android Studio |
| Эмулятор Android | запуск приложения без телефона | ставится из Android Studio |

При установке Android Studio выбери стандартный набор компонентов
(**Standard**): он сам скачает SDK, JDK и эмулятор.

Проверить, что всё установлено, можно в Android Studio:
**Settings → Languages & Frameworks → Android SDK** — должны быть отмечены
`Android SDK Platform 35`, `Android SDK Build-Tools`, `Android Emulator`,
`Android SDK Platform-Tools`.

## 2. Открыть проект

1. Скопируй папку проекта на компьютер (не запускай её из архива).
2. Android Studio → **File → Open** → выбери папку `tn-messenger`.
3. Дождись окончания **Gradle Sync**. Первый раз он скачивает библиотеки,
   это может занять 5–15 минут.
4. Если Android Studio просит указать SDK — выбери путь к установленному
   Android SDK (обычно `C:\Users\<имя>\AppData\Local\Android\Sdk`).

Файл `local.properties` в репозиторий не входит: Android Studio создаёт его сама
при открытии проекта. Если сборка не находит SDK, создай файл вручную:

```properties
sdk.dir=C:/Users/<имя>/AppData/Local/Android/Sdk
```

## 3. Настроить Firebase

Проект использует Firebase-проект `tn-messenger-e1585`. Настройки приложения
(`app/google-services.json`) уже лежат в репозитории, поэтому заново создавать
проект не нужно.

Нужно только включить продукты в [консоли Firebase](https://console.firebase.google.com):

### 3.1. Authentication

1. Проект `tn-messenger-e1585` → **Authentication** → **Get started**.
2. Вкладка **Sign-in method** → **Email/Password** → **Enable** → **Save**.

### 3.2. Realtime Database

1. **Realtime Database** → **Create Database**.
2. Регион — **europe-west1** (у учебного проекта база уже там).
3. Режим — **Start in locked mode** (правила добавим следующим шагом).
4. Скопируй адрес базы. У этого проекта он такой:

   ```
   https://tn-messenger-e1585-default-rtdb.europe-west1.firebasedatabase.app
   ```

   Если адрес другой, замени его в файле
   `core/data/src/main/java/com/sozvezdie/messenger/core/data/FirebaseConfig.kt`.

### 3.3. Правила доступа

Без правил Firebase запретит чтение и запись.

**Realtime Database → Rules** — вставь содержимое файла
[`firebase/database.rules.json`](../firebase/database.rules.json) и нажми **Publish**.

Правила разрешают читать чат и его вложения только участникам переписки.

### 3.4. Почему без Storage

Firebase Storage с недавних пор требует платный тариф (Blaze), поэтому проект
работает без него. Фото и файлы сохраняются прямо в Realtime Database
в кодировке Base64. Из-за этого есть ограничения: фото сжимаются до 1280 px,
документы — не больше 2 МБ. Для учебного прототипа этого достаточно.

## 4. Создать эмулятор

1. Android Studio → **Tools → Device Manager** → **Create Device**.
2. Выбери любой телефон, например **Pixel 6**.
3. Системный образ: **Android 13 (API 33)** или новее, вариант **x86_64**
   (на компьютерах с Apple Silicon — **arm64-v8a**).
4. Заверши создание и запусти эмулятор кнопкой ▶.

Если эмулятор не запускается и пишет про гипервизор, включи в BIOS
виртуализацию (Intel VT-x / AMD-V). На Windows также помогает установка
компонента **Android Emulator Hypervisor Driver** в SDK Manager.

## 5. Запуск приложения

1. В верхней панели Android Studio выбери конфигурацию **app**.
2. Выбери запущенный эмулятор.
3. Нажми **Run ▶** (Shift+F10).

Приложение установится и откроется на эмуляторе. Первый экран — вход.

## 6. Проверка двух аккаунтов

Мессенджеру нужны два пользователя. Способы:

- **Два эмулятора.** Запусти второй AVD и установи приложение на него
  (Run → выбрать второе устройство).
- **Эмулятор + телефон.** Включи на телефоне режим разработчика и отладку
  по USB, подключи его и запусти приложение на нём.

Порядок проверки:

1. Зарегистрируй первый аккаунт: имя, email, пароль (минимум 6 символов).
2. Выйди через иконку выхода в правом верхнем углу списка чатов.
3. Зарегистрируй второй аккаунт.
4. Войди первым аккаунтом → **Новый чат** → выбери второго пользователя.
5. Отправь сообщение. На втором устройстве войди вторым аккаунтом — сообщение
   появится в списке чатов, а внутри будет переписка.
6. Проверь фото (кнопка-скрепка → «Фотография»), файл (скрепка → «Файл»),
   галочки прочтения и надпись «печатает…».

## 7. Сборка APK

APK нужен, чтобы убедиться, что проект собирается, и передать приложение
другому человеку.

Из Android Studio: **Build → Build Bundle(s) / APK(s) → Build APK(s)**.

Из командной строки в папке проекта:

```bash
gradlew.bat assembleDebug
```

Windows PowerShell может потребовать `.\gradlew.bat assembleDebug`.

Готовый файл:

```
app/build/outputs/apk/debug/app-debug.apk
```

Установка на подключённый телефон или эмулятор:

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

`adb` находится в `Android SDK/platform-tools`.

## 8. Частые проблемы

| Симптом | Причина и решение |
| --- | --- |
| `SDK location not found` | нет `local.properties`; создай файл с `sdk.dir=...` (см. пункт 2) |
| `CONFIGURATION_NOT_FOUND` при входе | в Firebase не включён Email/Password (пункт 3.1) |
| `Permission denied` в чате | не опубликованы правила базы (пункт 3.3) |
| Сообщения не отправляются | неверный адрес базы в `FirebaseConfig.kt` |
| Фото не отправляется | нет правила для узла `media` — опубликуй правила из пункта 3.3 |
| «Файл больше 2 МБ» | ограничение прототипа: вложения хранятся в базе данных |
| Эмулятор не стартует | не включена виртуализация в BIOS |
| Долгая первая сборка | скачиваются зависимости Gradle и Firebase, это нормально |

## 9. Если создаётся новый Firebase-проект

Иногда проект приходится переносить на другой аккаунт Firebase. Тогда:

1. Создай проект и Android-приложение с package name `com.sozvezdie.messenger`.
2. Скачай новый `google-services.json` и положи его в папку `app/`.
3. Включи Authentication (Email/Password) и Realtime Database (Storage не нужен).
4. Замени адрес базы в `FirebaseConfig.kt` на новый.
5. Опубликуй правила из `firebase/database.rules.json`.
